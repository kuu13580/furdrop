# EXIF 送信者情報埋め込み — 仕様決定シート (確定版)

送信者が EXIF 埋め込みを選ぶ仕様を廃止し、**受信者がダウンロード時に決める**方式へ移す (R14 → R17)。
埋め込みは受信者ブラウザで実行する (presigned GET を fetch → EXIF 書き込み → 保存)。
Workers を経由させる案は `.claude/rules/workers.md` の「R2 は Presigned URL 経由・Workers を通してストリームしない」に反するため不採用。

> **その後の変更**: 一括 DL (R08) だけは iOS の Blob 制約でクライアント ZIP が成立せず、
> Workers 経由 + Workers 側での EXIF 書き込みに変えた (`server-zip-decisions.md`)。

## 決定事項

| ID | 論点 | 決定 |
|---|---|---|
| A1 | 記録先 EXIF 欄 | 受信者がラジオ3択で選ぶ: `記録しない` / `撮影者 (Artist) 欄のみ` / `カメラ機種 (Model) 欄にも記録`。ダイアログの初期選択は 3 番目 (Google フォト・iOS 写真アプリで表示されるため) |
| A2 | 元の `Model` 欄 | Artist のみ選択時は触らない。Model を選んだ場合のみ上書き (ダイアログで警告) |
| A3 | 書き込む文字列 | `Photo by ` + 送信者名 (先頭の `@` は除去)。**ASCII 固定・ローカライズしない** — Artist/Model は仕様上 ASCII 専用の欄で、非 ASCII は UTF-8 バイトを流し込む慣習頼みのため、英数字の送信者名なら純 ASCII に収まる形を優先 |
| A4 | 匿名写真 (`sender_name` NULL) | 無加工でスキップ |
| A5 | 他のフィールド | 何も書かない |
| B1 | 選ばせ方 | **初回 DL 時にダイアログ**を出して選ばせ、localStorage に保存。2 回目以降は即 DL |
| B2 | 保存場所 | localStorage (スキーマ変更なし) |
| B3 | 既定値 | 未設定 (= 記録しない)。初回 DL のダイアログで必ず一度は選ばせる |
| B4 | UI の置き場 | ギャラリーの選択バーと写真詳細の DL ボタン脇に「撮影者名: ○○ ▾」を常時表示し、押すと同じダイアログで変更 (実装時のボタン名は「ダウンロードオプション ▾」)。**設定画面 (S10) には置かない** (受信オプションではないため) |
| B5 | 埋め込み失敗時 | 無加工で保存し DL 自体は成功させる。ただし失敗したことは UI で伝える |
| C1 | `users.exif_embed_mode` | マイグレーション `0010` で DROP (実際には後続マイグレーションに分離) |
| C2 | `required` の意図保存 | DROP 前に `UPDATE users SET require_sender_name = 1 WHERE exif_embed_mode = 'required'` (`0010`) |
| C3 | 送信者への告知 | 出さない (名前の記録に同意した時点で、以後の扱いは受信者の自由) |
| D1 | `photos.camera_model` | カラムごと DROP。プライバシーポリシーの収集項目から外す判断 (E2) と整合させる |
| D2 | 既存写真の DL | D1 の結果、特別扱い不要。全写真を同じ経路で処理する |
| D3 | 要件 ID | 送信者機能 `S04` を削除し、受信者機能 `R17 DL時のEXIF埋め込み` を新設 |
| E1 | 利用規約 第14条 | 埋め込み方式の列挙から EXIF を外し、受信者の DL 時処理を別項として追記 |
| E2 | プライバシーポリシー | 収集項目から EXIF 関連 2 行を削除するだけ |
| E3 | LP コピー | 透かしに絞る |
| F1 | piexifjs のメモリ | APP1 セグメントだけを自前で splice する実装にする (dataURL 往復を避ける) |
| F2 | ZIP 内ファイル名 | 変更しない (送信者情報は各ファイルの EXIF に入る) |
| G1 | PR 分割 | **分割せず 1 PR** |

## 変更しないもの

- アップロード時のクライアント側 GPS 除去 (`stripExifGps`)。利用規約第14条3項が依存
- 透かしの 3 値制御 (`watermark_mode`) と `require_sender_name`
- 一括 DL の ZIP 構成・ファイル名 (`YYYYMMDD-HHMMSS_NN.jpg`)

## 記録

送信者が EXIF でクレジットを強制する手段は失われる (残るのは DB の `sender_name` と透かし)。
`requirements.md` 1.1 の差別化表はこれに合わせて書き換える。
